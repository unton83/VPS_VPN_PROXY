# Контекст проекта VPS_VPN_PROXY

## Краткое описание
- Тип: Система развертывания прокси/VPN-сервисов на VPS
- Цель: Автоматическое развертывание HTTP и Telegram прокси + WireGuard VPN с панелью
- Целевая платформа: Debian 11+ с Docker (ядро 5.6+ для WireGuard)

## Архитектурные решения
1. **Контейнеризация**: Все сервисы в Docker
2. **Оркестрация**: Docker Compose для каждого сервиса отдельно
3. **Безопасность**: Fail2Ban + ограничение доступа
4. **SSL**: Автоматическое получение Let's Encrypt
5. **Единый reverse proxy**: nginx в `telegram-proxy/` обслуживает Telegram (80/443) и панель WireGuard (8443); панель слушает только localhost (51821), наружу выходит через nginx с TLS

## Ключевые компоненты
- `http-proxy/` - 3proxy с аутентификацией (порт 8080)
- `telegram-proxy/` - telemt с FakeTLS (порт 443), сайт-прикрытие на nginx (порт 80), cover site (внутренний 8444), reverse proxy панели (8443)
- `wireguard-panel/` - wg-easy v15 (порт панели 51821 localhost, VPN 51820/udp), опционально AmneziaWG
- `fail2ban/` - защита от атак
- `deploy.sh` - основной скрипт развертывания

## Критические файлы
- `deploy.sh` - главный скрипт (~1060 строк)
- `http-proxy/3proxy.cfg` - конфигурация HTTP прокси
- `telegram-proxy/telemt.toml` - конфигурация Telegram прокси
- `telegram-proxy/nginx/vpn-panel.conf.template` - шаблон reverse proxy для панели
- `wireguard-panel/docker-compose.yml` - compose wg-easy
- `wireguard-panel/.env` - генерируемые параметры панели (пароль убирается после первого старта)
- `fail2ban/jail.local` - настройки Fail2Ban

## Известные проблемы, которые допускает автор
1. Безопасность: пароли в открытом виде в 3proxy.passwd - в виду того, что все операции выполняются от единственного пользователя root, прятать пароли не от кого
2. Конфигурация: отсутствие IP-фильтрации в 3proxy - не нужно, так как неизвестно, в каких приложениях будет подключен HTTP прокси
3. Версии: использование :latest тегов в Docker образах - автор надеется, что разработчики сервисов не изменят ключевых компонентов, но можно предложить зафиксировать мажорные версии (для wg-easy уже зафиксирован :15)
4. Пароль админа wg-easy: после первого старта INIT_PASSWORD удаляется из .env (остаётся только в deployment_info.txt) - при полной переустановке панели без данных потребуется сброс через UI
5. Порт 8443 для панели - нестандартный; в перспективе планируется единый 443 через ssl_preread (SNI-маршрутизация)

## Пути развития
1. Единый порт 443 для всех сервисов (nginx stream + ssl_preread: DOMAIN -> telemt, /wg/ -> панель)
2. Добавление OpenVPN и централизованное управление секретами
3. Проверить конфиги сервисов на соответствие официальной документации
4. Мониторинг сервисов и резервное копирование (backup/restore панели)
