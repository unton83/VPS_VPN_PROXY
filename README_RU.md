# Развертывание Сервисов VPS

Развертывание прокси-сервисов одной командой на VPS с низкими ресурсами (1CPU, 1GB RAM, 5GB Storage).

## Сервисы

- **HTTP Прокси (3proxy)** - HTTP прокси с аутентификацией
- **Telegram Прокси (telemt)** - MTProto прокси с маскировкой FakeTLS и сайтом-прикрытием
- **WireGuard Panel (wg-easy)** - VPN WireGuard с веб-панелью управления, опционально AmneziaWG

## Быстрый Старт

### Первым делом необходимо проверить доступность Телеграма из VPS

```bash
time curl -v https://api.telegram.org
```

### Развертывание в Одну Команду

```bash
bash <(curl -fsSL -H 'Cache-Control: no-cache, no-store' -H 'Pragma: no-cache' https://raw.githubusercontent.com/unton83/VPS_VPN_PROXY/master/deploy.sh)
```

### Ручное Развертывание

```bash
# Клонировать репозиторий
git clone https://github.com/unton83/VPS_VPN_PROXY.git
cd VPS_VPN_PROXY

# Сделать скрипт развертывания исполняемым
chmod +x deploy.sh

# Запустить развертывание
./deploy.sh
```

## Требования

- VPS с Debian 11+ (ядро 5.6+ для WireGuard)
- Docker + Docker Compose v2
- Домен с A-записью, указывающей на IP VPS (для Telegram прокси и панели WireGuard)
- Поддержка TUN (/dev/net/tun) — для WireGuard
- Открытые порты: 80, 443 (Telegram), 8080 (HTTP Прокси), 51820/UDP (WireGuard VPN), 8443/TCP (панель WireGuard)

## Конфигурация Сервисов

### HTTP Прокси (3proxy)
- **HTTP**: `VPS_IP:8080`
- **Аутентификация**: Автоматически сгенерированные логин и пароль
- **Пользователь**: user (учетные данные показаны после развертывания)

### Telegram Прокси (telemt)
- **Порт**: 443 (HTTPS)
- **Протокол**: MTProto с маскировкой FakeTLS
- **Сайт-прикрытие**: Обслуживается на порту 80
- **SSL**: Сертификаты Let's Encrypt с автообновлением
- **Прокси-ссылки**: Генерируются автоматически после развертывания

### WireGuard Panel (wg-easy)
- **Панель**: `https://ДОМЕН:8443` (через единый nginx reverse proxy с SSL)
- **Логин**: `admin`, пароль генерируется автоматически (сохраняется в `deployment_info.txt`)
- **VPN Endpoint**: `VPS_IP:51820/udp`
- **Данные**: хранятся в `wireguard-panel/data/` (конфиги клиентов, ключи)
- **Клиенты**: создаются через веб-панель (QR-коды, скачивание .conf)
- **AmneziaWG (опционально)**: обфускация протокола против DPI — включается по выбору при развертывании; требует установки модуля ядра `amneziawg` (автоматически через PPA; скрипт при необходимости включает source-репозитории `deb-src`) и AmneziaWG-совместимых клиентов

## Единый Reverse Proxy (nginx)

При выборе Telegram Прокси или/и WireGuard Panel разворачивается единый nginx gateway
(в каталоге `telegram-proxy/`):

| Порт | Назначение |
|------|------------|
| 80 | Сайт-прикрытие + HTTP-01 challenge для Let's Encrypt |
| 443 | telemt (FakeTLS MTProto) |
| 8443 | WireGuard Panel (https://ДОМЕН:8443) |
| 8444 | Внутренний: cover site для telemt (наружу не публикуется) |

Nginx и панель WireGuard связаны общей Docker-сетью `revers-proxy-net`: панель доступна nginx'у по имени контейнера `wg-easy`, а наружу порт панели 51821 не публикуется.

Если выбран только один из сервисов — nginx ставится для него. Если ни один — nginx не ставится.

## Варианты Развертывания

Скрипт развертывания предлагает следующие варианты:

1. **Только HTTP Прокси** - Развернуть только сервис 3proxy
2. **Только Telegram Прокси** - Развернуть только сервис telemt
3. **Только WireGuard Panel** - Развернуть только wg-easy (nginx для панели ставится автоматически)
4. **HTTP + Telegram** - Развернуть оба прокси
5. **Telegram + WireGuard** - Развернуть telegram-прокси и панель WireGuard
6. **HTTP + WireGuard** - Развернуть HTTP прокси и панель WireGuard
7. **Все сервисы** - Развернуть все сервисы
8. **Выход** - Отменить развертывание

## Использование Ресурсов

Все сервисы оптимизированы для VPS с низкими ресурсами:

| Сервис | Лимит CPU | Лимит Памяти | Сеть |
|--------|-----------|--------------|------|
| 3proxy | 0.3 ядра | 256MB | proxy-network |
| Nginx (Telegram) | 0.25 ядра | 256MB | telegram-network |
| Telemt | 0.4 ядра | 256MB | telegram-network |
| Certbot | 0.2 ядра | 128MB | telegram-network |
| wg-easy | 0.5 ядра | 512MB | default |

**Всего при всех сервисах**: ~1.65 ядер, ~1.4GB RAM (лимиты; фактическое потребление ниже).
На VPS 1CPU/1GB рекомендуется развертывать не все сервисы одновременно.

## Команды Управления

```bash
# Проверить статус сервисов
docker compose ps

# Просмотреть логи
docker compose logs -f 3proxy      # Логи HTTP прокси
docker compose logs -f telemt      # Логи Telegram прокси
docker compose logs -f web         # Логи Nginx
docker compose logs -f wg-easy     # Логи WireGuard панели

# Перезапустить сервисы
docker compose restart 3proxy
docker compose restart telemt
docker compose restart wg-easy

# Обновить сервисы
docker compose pull && docker compose up -d
```

Также доступен интерактивный скрипт управления: `./manage.sh`

## Функции Безопасности

- **Аутентификация**: Все прокси-сервисы требуют логин/пароль
- **TLS Шифрование**: Telegram прокси использует маскировку FakeTLS; панель WireGuard — за nginx с SSL
- **SSL Сертификаты**: Автоматические сертификаты Let's Encrypt с обновлением
- **Лимиты Ресурсов**: Ограничения контейнеров предотвращают злоупотребление ресурсами
- **Изоляция Сети**: Сервисы используют отдельные Docker сети
- **Панель WireGuard**: доступна только через HTTPS reverse proxy, порт 51821 привязан к localhost

### Конфигурация Fail2Ban

Скрипт развертывания автоматически устанавливает и настраивает Fail2Ban со следующей защитой:

- **SSH Защита**: Блокирует попытки подбора SSH пароля (3 попытки, бан на 1 час)
- **HTTP Аутентификация**: Блокирует неудачные попытки аутентификации прокси
- **Ограничение Скорости**: Предотвращает чрезмерные запросы к веб-сервисам
- **Защита от Ботов**: Блокирует вредоносный бот-трафик

**Команды Управления Fail2Ban:**
```bash
# Проверить статус Fail2Ban
sudo fail2ban-client status

# Проверить статус конкретной jail
sudo fail2ban-client status sshd
sudo fail2ban-client status nginx-http-auth

# Разблокировать IP
sudo fail2ban-client set sshd unbanip IP_АДРЕС

# Просмотреть заблокированные IP
sudo fail2ban-client banned
```

## Улучшения обработки ошибок

Скрипт развертывания теперь включает улучшенную обработку ошибок и механизмы отката:

- **Выполнение команд с проверкой ошибок**: Все критические команды выполняются через `run_cmd`, который логирует каждый шаг и проверяет коды выхода.
- **Автоматический откат при сбое**: Если установка Docker не удалась, скрипт пытается очистить частично установленные пакеты.
- **Откат развертывания сервисов**: Если развертывание любого сервиса завершается ошибкой, скрипт пытается остановить и удалить созданные контейнеры.
- **Строгий режим**: Скрипт использует `set -euo pipefail` для раннего обнаружения неустановленных переменных, ошибок конвейера и сбоев команд.
- **Детальное логирование**: Каждый шаг логируется с временными метками и индикаторами статуса для упрощения отладки.

Эти улучшения делают процесс развертывания более надежным и удобным для диагностики проблем.

## Устранение Неполадок

### Конфликты Портов
- Убедитесь, что порты 80, 443, 8080, 51820, 51821, 8443 не заняты
- Проверьте настройки файрвола: `sudo ufw status`

### Проблемы с Docker
- Проверьте, что Docker запущен: `sudo systemctl status docker`
- Проверьте версию Docker Compose: `docker compose version`

### Проблемы с Сертификатами
- Убедитесь, что A-запись домена указывает на IP VPS
- Проверьте логи certbot: `docker compose logs certbot`

### WireGuard не работает
- Проверьте наличие TUN: `ls -la /dev/net/tun`
- Проверьте, что UDP 51820 открыт в файрволе
- Проверьте статус интерфейса: `docker exec wg-easy wg show`
- При AmneziaWG: убедитесь, что модуль ядра загружен: `lsmod | grep amneziawg`

### Проблемы с Производительностью
- Мониторинг использования ресурсов: `docker stats`
- Проверьте логи контейнеров на наличие ошибок
